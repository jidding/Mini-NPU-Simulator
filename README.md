# Mini NPU Simulator

외부 수치 연산 라이브러리(NumPy 등) 없이 순수 Python 반복문만으로 AI 전용 칩(NPU)의 핵심 연산인 **MAC(Multiply-Accumulate)**을 구현하고, 입력 데이터 크기($N \times N$)에 따른 시간 복잡도($O(N^2)$)와 부동소수점 오차 처리를 분석하는 콘솔 시뮬레이터입니다.

## 1. 프로젝트 개요

- **개발 배경:** 컴퓨터는 시각적 패턴('십자가', 'X')을 0과 1(또는 실수)로 이루어진 2차원 숫자 배열로 인식하며, 기준 패턴인 **필터(Filter)**와 입력 패턴의 같은 위치 값을 곱하고 모두 누적해서 더하는 **MAC 연산**을 통해 유사도를 판별합니다.
- **NPU의 필요성:** 필터 크기($N \times N$)가 커질수록 연산량이 $N^2$에 비례해 기하급수적으로 증가합니다. 직렬 처리에 최적화된 기존 CPU와 달리 수많은 MAC 연산을 병렬 처리하는 NPU의 핵심 동작 원리를 Python으로 직접 시뮬레이션하고 검증합니다.
- **주요 기능:**
  1. **모드 1 (사용자 입력 3×3):** 3×3 필터 2개(A, B)와 패턴을 콘솔로 직접 입력받아 MAC 점수, 평균 연산 시간, 판정 결과 출력
  2. **모드 2 (`data.json` 분석):** 5×5, 13×13, 25×25 필터와 테스트 패턴을 일괄 로드하여 라벨 정규화, 스키마 검증, PASS/FAIL 판정 및 크기별 성능 표 출력
  3. **모드 3 (보너스 - 패턴 자동 생성 및 1D 최적화 비교):** 임의 크기 $N \times N$ 패턴을 자동 생성하고, 2차원 배열을 1차원 배열로 평탄화하여 연산 속도 향상률을 비교

## 2. 파일 구조

    Mini-NPU-Simulator/
    ├── main.py       # 시뮬레이터 메인 실행 파일 (MAC 연산, 입력 검증, 모드 1·2·3, 성능 측정)
    ├── data.json     # 모드 2 일괄 테스트용 필터(5×5, 13×13, 25×25) 및 패턴 데이터셋
    └── README.md     # 프로젝트 설명, 실행 방법, 실패 원인 및 시간 복잡도 결과 리포트

### 주요 함수 구성 (`main.py`)
- `mac_operation()`: 외부 라이브러리 없이 이중 `for` 반복문으로 $N \times N$ MAC 연산 수행
- `judge_scores()`: 허용오차(`1e-9`) 기준으로 두 필터 점수를 비교하여 판정 또는 동점(`UNDECIDED`) 반환
- `measure_mac_time()`: I/O 시간을 제외하고 순수 연산 함수 호출 구간만 반복 측정하여 평균 시간(ms) 산출
- `normalize_label()`: `'+'`, `'cross'`, `'x'` 등 혼재된 라벨을 표준 라벨(`Cross`, `X`)로 정규화
- `is_valid_matrix()`: 패턴과 필터가 기대 크기($N \times N$)와 일치하는지 검증하여 비정상 종료 방어
- `generate_cross_pattern()`, `generate_x_pattern()`: 임의 크기 $N \times N$ 테스트 패턴 자동 생성 (보너스)
- `flatten_matrix()`, `mac_operation_1d()`: 2차원 배열을 길이 $N^2$ 1차원 배열로 변환 후 단일 루프 연산 수행 (보너스)

## 3. 실행 방법

### 개발 환경
- **언어:** Python 3.8 이상 (Python 3.14 환경에서 테스트 완료)
- **사용 라이브러리:** Python 표준 라이브러리(`json`, `time`)만 사용 (NumPy, pandas 등 외부 라이브러리 미사용)

### 실행 절차
1. `main.py`와 `data.json`이 프로젝트 최상위 루트 디렉터리에 함께 위치해 있는지 확인합니다.

## 4. 핵심 구현 요약

### 1) `data.json` 키/라벨 규칙 해석 및 라벨 정규화
- `data.json` 내부에서 필터(`filters`)는 `'cross'`, `'x'` 키를 사용하는 반면, 패턴의 기대 정답(`expected`)은 `'+'`, `'x'` 기호를 사용합니다.
- 표기 불일치로 인한 오판정을 막기 위해 `normalize_label()` 함수를 구현하여 `'+'`와 `'cross'`는 **`Cross`**로, `'x'`는 **`X`**로 프로그램 내부 표준 라벨을 통일한 뒤 비교를 수행합니다.

### 2) 스키마 검증 및 예외 처리 정책
- **모드 1 입력 검증:** `input_matrix_3x3()`에서 한 줄당 공백 기준 원소 개수(`len(parts) != 3`)와 실수 변환(`float()`)을 검증하여, 빈 입력·행/열 불일치·문자 입력 시 안내 문구를 출력하고 해당 줄을 재입력받습니다.
- **모드 2 크기 불일치 방어:** 패턴 키(`size_{N}_{idx}`)에서 추출한 크기 $N$과 실제 2차원 배열의 행·열 길이를 `is_valid_matrix()`로 대조합니다. 불일치 발생 시 프로그램이 중단되지 않고 해당 케이스만 `FAIL`과 원인 메시지로 기록한 뒤 다음 테스트를 이어갑니다.

### 3) 부동소수점 오차 및 허용오차(`epsilon`) 기반 동점 처리
- 이진 부동소수점(IEEE 754) 실수 연산 특성상 수학적으로 동일한 값도 미세한 잔여 오차(예: `0.9` vs `0.8999999999999999`)가 발생합니다.
- 단순 대소 비교(`>`) 시 미세 오차로 특정 패턴에 치우쳐 오판정하는 문제를 방지하기 위해 **`EPSILON = 1e-9`** 기준을 적용했습니다. 두 점수의 절대 차이(`abs(score_a - score_b)`)가 `1e-9` 미만이면 **`UNDECIDED`(동점/판정 불가)**로 판정합니다.

## 5. 결과 리포트

### 1) `data.json` 테스트 요약 및 실패(FAIL) 원인 심층 분석
`data.json` 내 총 **6개**의 테스트 케이스를 분석한 결과 **통과(PASS) 3개, 실패(FAIL) 3개**가 집계되었습니다. 실패한 3개 케이스 모두 코드나 스키마 오류가 아니라 **수치 비교 문제(부동소수점 미세 오차에 따른 동점 처리 정책)**가 정상 작동하여 발생한 결과입니다.

- **`size_5_1` (FAIL — 수치 비교 / 동점 규칙):**
  - `Cross` 점수 `0.9` vs `X` 점수 `0.8999999999999999`
  - 두 점수의 차이는 약 $1.11 \times 10^{-16}$으로 수학적으로는 동점이나 부동소수점 표현 한계로 미세한 차이가 발생했습니다. 허용오차(`1e-9`) 정책에 의해 `UNDECIDED`로 판정되었으며, 단일 라벨(`X`)인 `expected`와 다르므로 `FAIL`로 분류되었습니다.
- **`size_13_2` (FAIL — 수치 비교 / 동점 규칙):**
  - `Cross` 점수 `7.499999999999997` vs `X` 점수 `7.5`
  - 두 점수의 차이는 약 $2.66 \times 10^{-15}$으로 `1e-9` 미만이므로 `UNDECIDED`로 판정되어 `expected`(`Cross`)와 불일치해 `FAIL` 처리되었습니다.
- **`size_25_1` (FAIL — 수치 비교 / 동점 규칙):**
  - `Cross` 점수 `4.9` vs `X` 점수 `4.899999999999999`
  - 두 점수의 차이는 약 $8.88 \times 10^{-16}$으로 역시 `UNDECIDED` 판정을 받아 `expected`(`X`)와 불일치해 `FAIL` 처리되었습니다.
- **진단 결론:** 만약 허용오차 정책 없이 단순 부등호로 비교했다면 부동소수점 노이즈 때문에 사실상 동점인 패턴을 특정 클래스로 잘못 확정했을 것입니다. `epsilon` 비교 정책을 통해 수치적 안정성을 확보할 수 있었습니다.

### 2) 크기별 성능 측정 표 및 시간 복잡도($O(N^2)$) 분석
I/O(파일 읽기, 콘솔 출력) 시간을 제외하고 순수 `mac_operation()` 호출 구간만 **10회 반복 측정**한 평균 연산 시간은 다음과 같습니다.

| 패턴 크기 ($N \times N$) | 평균 연산 시간 (ms) | 총 MAC 연산 횟수 ($N^2$) | 3×3 대비 연산량 증가 배율 |
| :---: | :---: | :---: | :---: |
| **3×3** | `0.0027 ms` | 9회 | 1.0배 |
| **5×5** | `0.0163 ms` | 25회 | 약 2.8배 |
| **13×13** | `0.0413 ms` | 169회 | 약 18.8배 |
| **25×25** | `0.0593 ms` | 625회 | 약 69.4배 |

- **시간 복잡도 $O(N^2)$ 근거:** 2차원 정사각 행렬의 MAC 연산은 바깥쪽 루프($N$회)와 안쪽 루프($N$회)가 중첩된 이중 반복문 구조이므로, 입력 한 변의 길이 $N$에 대해 정확히 $N \times N = N^2$번의 곱셈 및 누적 덧셈 연산을 수행합니다.
- **측정 결과 해석:** 입력 크기 $N$이 `3`에서 `25`로 약 8.3배 증가할 때 연산 횟수는 $9$회에서 $625$회로 약 **69.4배** 급증하며, 평균 연산 시간 역시 `0.0027 ms`에서 `0.0593 ms`로 비례하여 증가하는 $O(N^2)$ 추세를 보입니다. 실제 딥러닝 모델처럼 수백$\times$수백 크기의 필터 수천 개를 CPU처럼 순차 반복문으로 처리하면 심각한 연산 병목이 발생하므로, 수천 개의 MAC 연산을 동시에 수행하는 병렬 하드웨어(NPU)가 필수적임을 확인할 수 있습니다.

## 6. 보너스 과제 구현 및 성능 비교

### 1) 구현 내용
- **패턴 자동 생성기:** 크기 $N$을 입력받아 정중앙 행/열(`i == n // 2` or `j == n // 2`)을 채우는 `Cross` 패턴과 양 대각선(`i == j` or `i + j == n - 1`)을 채우는 `X` 패턴을 자동 생성합니다.
- **1차원 배열 메모리 접근 최적화:** $N \times N$ 2차원 리스트를 길이 $N^2$의 1차원 리스트로 평탄화(`flatten_matrix`)한 뒤 단일 루프(`mac_operation_1d`)로 연산하여, 2차원 리스트의 이중 포인터 참조 오버헤드와 안쪽 루프 제어 비용을 줄였습니다.

### 2) 최적화 전(2D) vs 후(1D) 성능 비교 결과 (동일 입력, 100회 반복 평균)

| 패턴 크기 ($N \times N$) | 2D 평균 시간 (ms) | 1D 평균 시간 (ms) | 속도 향상률 (%) | 연산 점수 일치 여부 |
| :---: | :---: | :---: | :---: | :---: |
| **3×3** | `0.0040 ms` | `0.0015 ms` | **63.1% 향상** | 일치 |
| **5×5** | `0.0058 ms` | `0.0031 ms` | **46.6% 향상** | 일치 |
| **13×13** | `0.0194 ms` | `0.0115 ms` | **40.8% 향상** | 일치 |
| **25×25** | `0.0470 ms` | `0.0328 ms` | **30.3% 향상** | 일치 |
| **51×51** | `0.2041 ms` | `0.1576 ms` | **22.8% 향상** | 일치 |

- **분석 결과:** 모든 크기에서 2D 연산과 1D 연산의 결과 점수가 오차 없이 일치했으며, 1차원 평탄화 접근 방식을 적용했을 때 **약 22.8% ~ 63.1%의 연산 속도 향상**을 달성했습니다. 이는 연속된 메모리 접근과 단일 루프 구조가 파이썬 인터프리터의 인덱싱 비용을 효과적으로 절감했음을 보여줍니다.

## 7. 과제 목표 핵심 정리

- **MAC 연산과 AI에서의 중요성:** 입력과 필터의 동일 위치 원소를 곱해 누적 합산하는 연산으로, 신경망 특징 추출(Convolution)의 핵심이며 전체 AI 연산의 대부분을 차지합니다.
- **유사도 계산 원리:** 입력 패턴과 필터의 `1` 위치가 겹칠수록 곱셈 결과(`1×1=1`)가 많이 누적되어 높은 점수를 얻고, 겹치지 않으면 `0`이 되어 낮은 점수를 얻는 내적(Dot Product) 원리를 이용합니다.
- **라벨 정규화 이유:** 외부 데이터(`data.json`)의 제각각인 표기(`+`, `cross` 등)를 내부 표준 라벨(`Cross`, `X`)로 통일해야 조건 분기와 PASS/FAIL 검증 로직을 일관되게 유지할 수 있습니다.
- **허용오차(`epsilon`) 필요성:** 실수 연산의 미세 오차로 동점 데이터가 한쪽으로 잘못 판정되는 것을 막기 위해 `abs(a - b) < 1e-9` 기준의 동점 판별 정책이 필수적입니다.
- **실패 원인 분리 진단:** 테스트 실패 시 ① 데이터/스키마 문제(키 누락, 배열 크기 불일치), ② 로직 문제(인덱스 오류, 라벨 매핑 누락), ③ 수치 비교 문제(부동소수점 오차)로 원인을 분리해 체계적으로 개선할 수 있습니다.
